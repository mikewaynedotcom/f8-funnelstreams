## 3. Deploy the isolated endpoint

**Preferred: Cloudflare Workers.** Create a new Worker in Mike's authorized account. Link the repo and select branch dot/skills-mcp-pilot, root mcp-skills-pilot. Use `npm ci` and `npm run build`. Add a Wrangler configuration for the NEW Worker (name matches dashboard, main = dist/worker.mjs, validated compatibility date), then deploy with `npx wrangler deploy` via the authorized account. If Git integration is used, restrict it to this branch and root. Set `ALLOWED_HOSTS` as a runtime variable to the exact assigned workers.dev hostname, not a URL; `ALLOWED_ORIGINS` only for verified required origins, such as https://claude.ai. Do not use wildcard origins or remove the host guard. Configure host request/rate limits within the approved plan. Use the assigned HTTPS domain; no custom domain needed.

**Alternative: Node.** Use the supplied Dockerfile and npm start, HOST=0.0.0.0, assigned PORT, exact ALLOWED_HOSTS and ALLOWED_ORIGIN_HOSTS if required. Configure trusted TLS and rate limits. Test this new host independently.

## 6. Updates, rollback and support

- Every approved change originates in its canonical skill repository. Copy exact approved content at an immutable commit, update manifest and hashes, run tests, deploy review release to isolated host, check /health, then verify Claude actually sees the new version and asks for fresh approval when required. Do not auto-publish arbitrary mutable main changes.
- Rollback: redeploy previous known-good immutable build; verify /health and Claude native retrieval. Preserve existing downloads and production Help. For missing skill, check eligibility first; for missing citations, check separate Help connection. For failed integrity, quarantine the release, do not disable validation. For lack of hosting or sign-in, stop that step, report precise dependency, continue authorized offline preparation.
- Never store tokens or customer data in Git, logs or shared receipts. No payment/CRM mutation. If a provider imposes a stop, respect it. Document any unresolved feature limitation instead of claiming success.

Record the exact receipt. Full rollout done only when every intended authorized catalog entry is delivered and validated or explicitly held; protected material remains protected.
